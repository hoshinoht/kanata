API reference

Examples use $KANATA_API_KEY. Set it in your local environment. Your key is never included in copied examples.

Generic examples use placeholder aliases. Endpoint availability and optional features depend on your key and the configured routes.

POST /v1/chat/completions accepts JSON with model and messages. POST /v1/audio/transcriptions accepts multipart form data with model and file. Both require an Authorization: Bearer header.

List models · GET /v1/models

Returns only configured, bound routes allowed by your key and this listener. Listing a model does not confirm backend health. Refresh access after a key or route change.

Errors and request limits

Errors use {"error":{"message":"…","type":"…","param":null,"code":"…"}}. A field error may name the rejected parameter.

400
Invalid or unsupported input. Check the error’s param.
401 / 403
Invalid, expired or revoked key, or access denied for this model and operation.
408 / 413
Upload timed out or the request exceeded the configured size limit.
429 / 503
Key, queue or upload capacity reached, or backend unavailable. Honor Retry-After when present.
502 / 504
Backend response failure or timeout.

Unknown request fields are rejected. Permissions and limits are enforced on every API request.
